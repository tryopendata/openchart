## Value labels

`format: ".1f"` matches the one decimal place in the source data, and `axis: false` drops the y axis because the labels already carry the numbers. `density` decides how many labels show. The default, `"auto"`, hides any label that would collide with a neighbour; all 24 fit here, so none is dropped. `"all"` prints every label even when they collide, `"endpoints"` only the first and last, and `"none"` none. `prefix` and `suffix` add text around each value.

## Legend position

<Demo id="framing/legend-top" />

A `nominal` field on `color` gets a legend. Without a setting, the engine picks the position from the chart's width; `legend: { position: "top" }` fixes it above the plot. The other positions are `"right"`, `"bottom"`, `"top-left"`, `"bottom-right"` and `"inline"`. `scale.domain` on the color channel sets the order of the legend and which color each source gets. The stack follows the order of the rows, so this spec lists the sources in the domain in the same order the data does.

## Labels in place of a legend

<Demo id="framing/labels-direct" />

A legend makes the reader match colors back to the plot. Here each band is named at its right end instead. Stacked areas show these names only when `endpointLabels` is set, and `content: "label"` prints the name without the value. `legend: { show: false }` removes the legend the names replace.

## Fields that matter

| Field | What it does |
| --- | --- |
| `labels` | `true`, `false` or a config object for value labels. |
| `labels.density` | `"auto"`, `"all"`, `"endpoints"` or `"none"`. |
| `labels.format` | d3-format string for the value. |
| `labels.prefix`, `labels.suffix` | Text before and after each value. |
| `labels.placement` | `"inside"`, `"outside"` or `"adaptive"` for bar labels. |
| `legend.position` | Where the legend goes. Omit it to let the width decide. |
| `legend.show` | `false` hides the legend. |
| `endpointLabels` | Names each line or band at its right end. Stacked areas need it set explicitly. |
