Do most states have about the same median household income, or are they spread out? A histogram of the 2024 values from the [Census Bureau's American Community Survey](https://www.census.gov/programs-surveys/acs) can say either, and the width of its bins decides which. A histogram sorts values into bins and draws a bar for each bin's count, so the same values can look like a lump, a smooth curve or random spikes.

The data covers the 50 states and DC. The lowest is Mississippi at $59,127 and the highest is DC at $109,707.

## Too few bins

With wide bins everything lands in two or three bars, and the chart shows only a hump with no detail inside it.

<Demo id="blog/income-bins-25000" />

The chart puts most states between $75,000 and $100,000 but cannot show whether those values bunch together or spread out.

## Too many bins

With narrow bins most bars hold one or two states, and the outline jumps around from one bar to the next.

<Demo id="blog/income-bins-1000" />

A reader will see peaks and gaps here, but each is one or two states, and moving a state by $1,000 would reshuffle them.

## $10,000 bins

A $10,000 bin gives six bars. The values pile up between $70,000 and $90,000, and a thinner tail runs to the right.

## Sturges and Freedman-Diaconis rules

Two rules compute a starting width from the data. Sturges' rule uses only the count of values: take the base-2 logarithm of 51, add one and round up, which gives 7 bins, or about $7,200 each across this range. The Freedman-Diaconis rule sets the width to twice the spread of the middle half of the values (the interquartile range) divided by the cube root of the count. Because it ignores the extremes, an outlier like DC barely moves it. It gives about $9,400.

Both rules land near the $10,000 width. Keep every bin the same width: the eye reads a bar's area while the count sets only its height, so bars of unequal width stop meaning the same thing. Try a width on either side of the suggestion and see whether the picture changes.

## Checking a feature at a second bin width

Redraw the chart at another width to tell a real feature from an artifact of the bin edges. Here is the USGS earthquake catalog for January 2026, counted in 0.1-magnitude bins, with only the quakes of magnitude 2.5 and above.

<Demo id="blog/quakes-bins-0-1" />

Small quakes are far more common than big ones, so counts should fall steadily with magnitude. Instead they dip to 8 at magnitude 3.9 and climb back by 4.5.

<Demo id="blog/quakes-bins-0-5" />

At half-magnitude bins the small spikes at higher magnitudes smooth out, and the dip stays, so the bins did not make it. The way the catalog was collected probably did. Outside regions with dense seismometers, such as the United States, the catalog reliably includes only quakes of about magnitude 4.5 and up. Counts climb from 4.0 and peak at 4.5, where worldwide coverage begins.

To check whether the data collection made a feature, read how the data was gathered.

## The spec

OpenChart's `histogram` mark bins and counts raw rows for you. `mark: { type: "histogram", binCount: 24 }` asks for up to 24 bins and picks a round width, and `encoding.x.bin: { step, extent }` sets an exact width. The charts here use the `bin` [transform](/docs/the-spec/transforms/) instead, because the earthquake rows are already counted and have to be summed, which the mark's count can't do. The income charts use the same transform so the two specs match.

In the income spec, `bin: { step: 10000, extent: [50000, 125000] }` writes each state's bin start and end into two new fields. `aggregate` with `op: "count"`, grouped by both fields, turns 51 rows into one count per bin.

The bin start goes on `x` and the bin end on `x2`, so each bar spans its whole range. A `scale.domain` fixes the x range so every width is drawn on the same axis, and `axis.values` puts the ticks on bin edges ($50k, $70k and so on) so a reader can see where each bar starts. The bar color is a `{ light, dark }` pair in `theme.colors.categorical`, which picks a lighter teal on a dark page.

The earthquake rows are already counts per 0.1 magnitude, so the first earthquake chart draws them directly, each bar ending 0.1 above its start. The 0.5 chart merges them with a `bin` transform and `op: "sum"` on the count field.

A [density curve](/docs/distribution/density/) avoids bin edges entirely, in exchange for choosing a bandwidth, which sets how far each value is smeared across its neighbors.

Every field the mark takes, including `binCount`, is on the [histogram page](/docs/distribution/histogram/).
